# Nocturne Grid

## Identity

Nocturne Grid is an experimental visual direction exploring the
relationship between digital interfaces and physical architecture.

The central idea is:

> a website experienced as a constructed space rather than a document.

The microsite should feel like entering an imaginary architectural
studio, digital observatory, or experimental building whose structure
is continuously being revealed to the visitor.

This is not a real architecture company.

The website itself is the architectural object.

The visitor should feel as though they are moving through a system
of rooms, surfaces, corridors, measurements, voids, and structural
elements.

---

# Conceptual qualities

The experience should feel:

* architectural
* contemporary
* spatial
* precise
* restrained
* cinematic
* intelligent
* mysterious
* tactile
* experimental
* confident

The design should create tension between:

* physical / digital
* solid / empty
* static / kinetic
* structure / freedom
* geometry / human presence
* darkness / illumination
* precision / ambiguity

Avoid making the aesthetic feel like generic "cyberpunk", generic
"futurism", or a typical technology landing page.

The design should feel closer to experimental architecture,
contemporary graphic design, spatial installations, and art
direction.

---

# Visual direction

The aesthetic should be substantially different from both the
Root Tecnologías website and the Terminal Bloom microsite.

Do not reuse Terminal Bloom's botanical, archival, specimen,
paper, serif-editorial, or retro-computational visual language.

The primary visual territory should be:

* deep graphite or near-black surfaces
* warm white or off-white typography
* extremely restrained use of a single accent color
* thin structural lines
* large areas of negative space
* geometric divisions
* architectural photography or abstract architectural imagery
* oversized coordinates and measurements
* cropped elements
* asymmetric compositions
* rigid alignment systems
* large planes intersecting with smaller information
* strong contrast between scale

The page should feel intentionally sparse.

Do not fill empty space simply because it exists.

Whitespace is part of the architecture.

Avoid:

* excessive gradients
* glassmorphism
* glowing neon everywhere
* floating rounded cards
* generic dashboards
* generic SaaS layouts
* excessive shadows
* excessive border-radius
* decorative blobs
* conventional hero illustrations
* stock-photo-heavy layouts

---

# Color system

Use a restrained palette.

The background should primarily be a very dark neutral.

Typography should primarily use a warm white or similarly restrained
light neutral.

Introduce only one meaningful accent color.

The accent should behave like architectural lighting or a construction
marker rather than a decorative brand color.

For example, it could be:

* safety orange
* construction yellow
* muted signal red
* highly controlled electric blue

Choose one.

Do not use multiple competing accent colors.

The aesthetic should still work if the accent color is temporarily
removed.

---

# Typography

Typography is a major part of the visual identity.

Prefer a contemporary grotesk or neo-grotesk sans-serif for primary
content.

A monospace or technical face may be used sparingly for:

* coordinates
* measurements
* timestamps
* system labels
* section indexes
* navigation metadata

Do not use a serif as the primary typeface.

Typography should feel architectural rather than editorial.

Use scale deliberately.

Large typography may function as a structural element, but avoid
turning every heading into oversized marketing text.

Some text should be intentionally small.

Create a strong relationship between:

* very large type
* small technical annotations
* medium informational text
* empty space

---

# Layout philosophy

The page should behave like a floor plan translated into a digital
interface.

Do not build the page as a sequence of conventional marketing
sections.

Instead, think in terms of:

* rooms
* thresholds
* corridors
* planes
* coordinates
* structural axes
* voids
* elevations
* observation points
* intersections

The composition should occasionally feel asymmetrical.

Elements do not always need to align to a conventional centered
container.

Use a strong underlying grid, but allow selected elements to escape
or cross that grid.

Structural lines may continue across multiple sections.

A vertical axis or coordinate system may become a recurring visual
motif.

The visitor should gradually understand the spatial system as they
scroll.

---

# Required website structure

Build a complete one-page landing page.

The exact composition is intentionally flexible.

The page should contain enough fictional content to demonstrate the
aesthetic as a complete professional design study.

At minimum, include the following conceptual areas.

---

## Navigation / Entry

Create a navigation system that feels like an architectural control
surface rather than a conventional website header.

It should not resemble the Root Tecnologías navigation.

Possible concepts include:

* coordinates
* project number
* current spatial position
* section index
* compact typographic navigation

Do not make the navigation unnecessarily complicated.

Include a subtle return action:

`← BACK TO AESTHETIC`

It must navigate to:

`/esteticas/nocturne-grid`

Use the same browser tab.

The return action should visually belong to Nocturne Grid.

---

# Opening / Threshold

The opening should feel like crossing into a physical space.

Do not use a conventional:

"Welcome to..."

Instead, establish the fictional world immediately.

Possible conceptual language:

* PROJECT 07
* NIGHT STRUCTURE
* FIELD / 04
* OBSERVATION DECK
* 04° / 17° / 92°
* STRUCTURE UNDER LIGHT

These are examples of tone, not text that must be copied.

The opening composition should contain:

* a strong title
* a small amount of technical metadata
* a large spatial or geometric visual
* an indication that the visitor is entering the system

The first viewport should be visually striking without becoming
visually noisy.

---

# Spatial map / Architecture

Create a major section that behaves like a simplified architectural
plan.

It could represent an imaginary structure, installation, or digital
building.

Do not simply display a conventional diagram.

The visitor should be able to visually understand:

* different zones
* paths
* intersections
* observation points
* structural boundaries

Use CSS/SVG-generated geometry where appropriate.

The structure should feel native to the website rather than like an
embedded external diagram.

Selected points may reveal information on hover or keyboard focus.

---

# Projects / Structures

Create a collection of fictional architectural studies.

Do not display these as ordinary cards.

Instead, treat them as a sequence of architectural plates or
project elevations.

Each project may include:

* project number
* name
* location
* year
* dimensions
* status
* short description

The projects should have different visual compositions.

For example:

PROJECT 01 could be primarily typography and geometry.

PROJECT 02 could emphasize an image.

PROJECT 03 could be mostly empty space with a small amount of
information.

PROJECT 04 could use a large numerical measurement as its primary
visual element.

The collection should demonstrate that the grid is a system rather
than a repeated card template.

---

# Featured structure

Create one dominant architectural composition.

This is the visual centerpiece of the page.

It could represent:

* an imaginary building
* a tower
* a bridge
* an underground structure
* a spatial installation
* an abstract architectural volume

Prefer CSS, SVG, geometric forms, or carefully treated imagery.

Do not rely on generic stock photography.

The featured structure should feel like an object existing inside
the website.

Consider using:

* perspective
* layered planes
* line drawings
* wireframe-like geometry
* image cropping
* scale changes
* subtle parallax
* controlled illumination

Do not make it look like a 3D-rendering showcase.

Graphic design should remain as important as the object itself.

---

# Measurements / Data

Introduce a section where the fictional architecture is described
through measurements and observations.

Possible data:

* height
* width
* depth
* occupied area
* structural density
* orientation
* light exposure
* material
* observation time
* coordinates

The data should not appear as a generic statistics row.

Integrate measurements into the architecture of the page.

For example:

A giant `84.2 M` could represent height.

A small annotation could identify it as:

`VERTICAL EXTENT`

Another value could sit along a structural line.

The numbers should feel like part of the space.

---

# Human scale

Introduce a quieter section that reminds the visitor that the
architecture exists for people.

Avoid corporate "Our mission" language.

Instead, explore ideas such as:

* scale
* movement
* distance
* occupation
* light
* silence
* perspective

The copy should be short and atmospheric.

For example, the conceptual idea might be:

A structure becomes architecture only when someone moves through it.

Do not copy this sentence literally unless it fits the final design.

This section should provide contrast against the technical and
geometric portions of the page.

---

# Interaction

Include several meaningful interactions.

Possible interactions include:

* architectural points becoming active on hover/focus
* sections revealing additional measurements
* a coordinate indicator changing as the visitor scrolls
* a structural line following the current section
* subtle image movement
* controlled perspective shifts
* project information appearing through spatial transitions
* navigation indicating the visitor's current position

Do not animate everything.

Motion should communicate:

* movement through space
* changing perspective
* structural transformation
* illumination
* discovery

Avoid animation whose only purpose is decoration.

All interactions must remain usable with keyboard navigation.

Respect:

`prefers-reduced-motion`

When reduced motion is requested, provide an equally usable static
experience.

---

# Scroll behavior

Scrolling should feel like moving through architecture.

Consider creating transitions where one composition gradually gives way
to another rather than using standard section-to-section fades.

Potential techniques include:

* pinned visual structures
* changing coordinates
* line movement
* controlled transforms
* scale transitions
* clipping
* architectural planes entering or leaving the viewport

Do not turn the page into an experimental animation demo.

The content must remain readable and navigation must remain obvious.

Normal browser scrolling should remain usable.

---

# Responsive behavior

The design must work intentionally on:

* desktop
* tablet
* mobile

Do not simply shrink the desktop composition.

On smaller screens:

* simplify the architectural grid where necessary
* preserve the spatial concept
* reconsider large geometric compositions
* transform horizontal compositions into vertical relationships
* ensure technical annotations remain readable
* avoid tiny text
* avoid horizontal overflow

Mobile should feel like a different scale of the same architecture,
not a broken desktop layout.

---

# Imagery

If imagery is used, it should support the architectural concept.

Prefer:

* brutalist architecture
* abstract structures
* concrete surfaces
* night architecture
* structural details
* geometric shadows
* empty interiors
* experimental installations

Avoid recognizable commercial architecture brands or overly
familiar landmarks unless there is a deliberate reason.

Do not create a page that depends entirely on photography.

The design system must remain visually compelling without images.

---

# Content

All visible content should feel intentional and belong to the
fictional Nocturne Grid world.

Use fictional but coherent project names, measurements,
coordinates, observations, and descriptions.

Do not use:

* Lorem ipsum
* placeholder text
* "Coming soon"
* "Content goes here"
* "Example text"
* generic agency marketing copy
* references to AI generation

The page should feel complete when opened for the first time.

---

# Technical requirements

Implement this as part of the existing Vue application.

Create an isolated aesthetic implementation.

Prefer a structure such as:

`src/aesthetics/nocturne-grid/`

Possible structure:

`src/aesthetics/nocturne-grid/NocturneGrid.vue`

`src/aesthetics/nocturne-grid/nocturne-grid.css`

Additional components may be created if they provide meaningful
separation or reuse.

Keep aesthetic-specific CSS and components isolated from the main
Root Tecnologías design system.

Do not modify the visual identity of:

* `/`
* `/esteticas`
* `/esteticas/:slug`
* `/lab`
* `/contacto`

unless a change is explicitly required for routing integration.

Do not introduce a UI framework.

Prefer native Vue, CSS, and SVG where appropriate.

Avoid unnecessary dependencies.

---

# Accessibility

The microsite must remain usable and semantically structured.

Ensure:

* keyboard navigation
* visible focus states
* sufficient text contrast
* meaningful heading hierarchy
* semantic landmarks
* accessible interactive elements
* appropriate labels for technical controls
* no information conveyed exclusively through color
* reduced-motion support

Do not sacrifice usability for visual experimentation.

---

# Performance

Keep the experience performant.

Avoid:

* unnecessarily large assets
* continuous expensive animations
* excessive DOM complexity
* animation of layout properties when transforms can be used
* unnecessary third-party libraries

Prefer CSS transforms and opacity for animation.

If imagery is used, ensure it is appropriately sized.

---

# Important creative constraints

Do not produce a generic futuristic website.

Do not produce a cyberpunk website.

Do not produce a SaaS dashboard.

Do not produce a conventional architecture agency website.

Do not make every section look like the same card repeated twelve
times.

Do not make every element glow.

Do not use a large gradient as the primary visual identity.

Do not use rounded glass panels as the main interface metaphor.

The design should communicate architecture through:

* proportion
* space
* structure
* alignment
* geometry
* scale
* movement
* typography

The most important visual idea is:

> the website itself should feel constructed.

The visitor should feel that they are navigating a designed spatial
system rather than scrolling through a collection of marketing
sections.

---

# Relationship to Terminal Bloom

Nocturne Grid must be clearly distinguishable from Terminal Bloom.

Terminal Bloom explores:

`organic life + archival computation`

Nocturne Grid explores:

`architecture + digital space`

Do not reuse Terminal Bloom's:

* botanical imagery
* specimen terminology
* aged-paper aesthetic
* botanical serif typography
* warm archival interface
* field-notebook composition
* specimen cards
* botanical labels

Shared technical architecture is acceptable.

Shared visual language is not required.

---

# Definition of done

When:

`/esteticas/nocturne-grid/live`

is opened, it should feel like entering a completely different
website.

The experience should communicate its concept before the visitor
reads the explanatory text.

The visitor should understand the aesthetic through:

* spatial composition
* typography
* geometry
* interaction
* motion
* content
* negative space

The final result should feel like a deliberate contemporary design
direction that could plausibly appear in a professional creative
technology studio portfolio.

It should demonstrate visual range relative to Terminal Bloom rather
than appearing to be another theme built from the same template.
